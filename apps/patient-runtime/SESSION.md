## Decisions
- **An envelope that can't be sealed yet is not stored as plaintext.** When the org key is missing (404) or the network is off, nothing is queued. The session counts as pending (approved while sharing, no envelope yet), and the retry worker rebuilds the payload from the stored coded rows, which gives the same payload every time, then seals it. The outbox only ever holds the sealed envelope.
- **Turning the care team off stops future sharing on the device at once (CN-03)**, even before the service hears about it. A check-in approved while sharing was off is never sealed later, even if sharing is turned back on.
- **Each consent update carries the full state, so an older queued one is marked `failed` (superseded, never sent)** when a newer one is queued; an older update landing after a newer one would undo it. Consent goes first in the retry order, so a withdrawal reaches the service before later sends.
- **The trend is computed on this device** from its own approved check-ins (up to 7 including today). The device doesn't hold the seeded service history, so Walter's first check-in here reads "unknown".
- **The envelope receipt shows the plaintext hash** (brief 26.13, `send_envelope`). The org key is fetched fresh for every envelope and never taken from the cache, because an organization may register a new key.
- **One envelope per organization** (D-064, D-065): the care team, plus each emergency hospital when emergency consent is on both now and when the check-in was approved. The latter is the consent row with the highest id whose `updated_at` is no later than the approval, compared to the second. Each organization waits for its own key, so a missing Lakeside key never holds up Northgate.
- **The setup screen's choices come from `schema/demo_fixtures.json`** (organizations, and this patient's caregivers): the service has no organization directory a patient device can read. Ask the company owner for one before real use.
- **Setup replaces the whole choice,** like the service (D-067). Contacts get new `ec_` ids on every save, labels stay in `emergency_contact.display_label`, and without emergency consent no hospitals or contacts are kept or sent. A new care team clears the cached key.
- **The consent switches are a second send path,** approved by the user for A7. They only send the consent update, through `egress_gate.send_queued`, with a receipt.
- **"Network off" in the live check means the local service was stopped**: connection refused, the same as no network for the egress gate. I can't switch off the laptop's network from here; speech, filter and model run locally either way.
- **Severe alerts are queued at approval, in the same transaction as the record, and sent first.** They go only with consent to share with the care team or the caregiver; the service decides who receives them. The payload is minimal (AL-03): no symptom details.
- **The alert reply has no `payload_sha256`**, so alert receipts are checked by the canonical hash and the service's 200 on a resend. The company side could add the hash to the reply.
- **The retry worker gets its own client**, because it closes its client after each pass; it never uses the shared one. Attempt counts are kept in memory.
- **"pardon?" counts as a "repeat" command, not a no-answer**, and commands don't use up the two re-asks.
- **One correction per check-in** (VC-08). A spoken change that isn't understood doesn't use it up, and nothing about it is ever guessed.
- **Rating rules override the model.**
  - Only the rules can return `no_answer`; when the model says "no answer" about real words, that becomes `off_topic`.
  - Rambling means a long answer (over 40 words, or several sentences over 30 words) in which at least 40% of the words are off topic; an answer of 20 words or fewer is never rambling.
  - The model chooses sentence numbers, and the rater copies those sentences from the patient's own words.
- **`rating.py` imports no network code.** It reaches the model only through `extract.py`'s loopback-checked client, so the guard still allows `ollama` in `extract.py` alone.
- **Any answer that isn't complete is re-asked (VC-05), rambling included.** The relevant part of a rambling answer is still used, and after 2 re-asks the question counts as unanswered.
  - On the patient screen, moving on after a give-up waits for a tap.
  - A re-ask plays the simpler wording automatically, with "Let me ask that more simply."
- **Only `POST /checkin/sessions/{id}/approve` sends** (PV-04). The summary shows the exact record that will go, and approval sends that same record (same `record_id`, same hash). Approving again returns the stored receipt; a record kept while offline is resent unchanged (D-021).
- **The survey and term list are fetched at the start of each check-in**, through `egress_gate.refresh_config`. If offline, the cache is used. With no cache, the check-in can't start (503); there is no stand-in survey any more.
- **A missing severity is never guessed** (VC-10). The summary lists it in `needs_severity`, and the patient picks Mild, Moderate or Severe; approval is refused until then.
  - Record `status` is `completed` when every question was answered, otherwise `partial`.
  - `possible_link_flag` is always false until exposure linking (SE-04) is built.
- **Only wellbeing, symptom-screen and exposure questions add symptoms**, and the model runs only for those. Answers to the severity and onset questions fill in only the symptoms from the latest answer that reported any. Both rules came from the live run (see Errors and fixes).
- **Rules override the model in `extract.py`** (Scoping Doc 17.1):
  - A specific code is kept only if the text contains a cue for it (schema words plus a curated cue list); otherwise it becomes `SE_OTHER_REVIEW`.
  - "unsure" from the model becomes `SE_OTHER_REVIEW` unless the patient used the term's own schema words.
  - Denied and stopped symptoms are dropped.
  - Severity and onset are kept only if the text supports them.
- **The check-in draft lives in memory.** If the runtime restarts mid check-in, the answers are kept but the coded symptoms of earlier answers are lost (A6).
- **Config fetches can't go in `egress_log`** (PV-06). `egress_log.outbox_id` is required and must point to an outbox row, and the outbox allows only the four send destinations. So survey and term fetches go to the Python log (method, path, status) only; ask the company owner whether to change the schema.
  - A 5xx reply reached the service, so it is logged in `egress_log`, and the record stays queued.
  - A transport error reached nothing and is not logged.
  - A refused record (4xx) is marked `failed` and never resent.
- **`apps/patient-web/.gitignore`** ignores `.vite/` (Vite's cache), because the root `.gitignore` belongs to the company owner.
- **Local model calls are not egress.** `extract.py` may import the `ollama` client (and nothing else on the network list) to reach Ollama on this device. The host must be exactly `127.0.0.1`, `::1` or `localhost`. That is checked at startup (`main.py` fails fast) and on every call, and the import guard test allows `ollama` only in `extract.py`. Ask the company owner to reword the brief's "any HTTP library" rule to say "anything that reaches beyond this device".
- **Models are fetched once at setup, never during a check-in.**
  - Whisper loads with `local_files_only=True`; fetch it with `uv run python -m sentinel_patient.stt --download`.
  - spaCy `en_core_web_lg` 3.8.0 is a pinned wheel in `pyproject.toml`; Presidio is set up so it never downloads a model.
  - The Ollama model comes from `ollama pull llama3.2:3b`.
  - A voice test blocks sockets to prove that transcription makes no network request (VC-02).
- **Speech-to-text decodes in memory with PyAV and passes faster-whisper the samples.** faster-whisper 1.2.1's own decoder is broken with PyAV 19 (see Errors and fixes); don't simplify this back to passing raw bytes. Only browser formats are decoded (`matroska,webm,ogg,mov,mp4,wav,mp3,flac,aac`), so FFmpeg formats that can open URLs or files are ruled out.
- **VC-03 decoding settings:** `vad_filter=True`, `min_silence_duration_ms=1000`, `speech_pad_ms=400`, `condition_on_previous_text=False`. Speech on both sides of a 3 s pause (silence or room noise) is kept, and silence alone returns "". When an answer ends is decided by the screen: only the patient's second tap stops the recording.
- **Answer button is a toggle** (tap to start, tap to stop), not hold-to-talk, because holding is hard at 92.
- **Question audio comes from the runtime** (`say` at 170 wpm, or 60 wpm for "Slower"), never from the browser's `speechSynthesis`, which may use cloud voices. Text goes to `say` on stdin, never on the command line.
- **Filter rules:**
  - Organization names (hospitals, pharmacies) are redacted as `[PLACE]`.
  - Any full date with a year is redacted as `[DATE_OF_BIRTH]`, which also removes visit dates.
  - Relative time phrases are kept, because extraction needs them for onset.
  - Words from `schema/terms.json`, severity words and time words are never redacted.
  - Presidio's logger is kept at WARNING, because its DEBUG output contains words from the text.
- **Extraction guards against model guesses:** with no severity words in the text, severity becomes None and is re-asked (VC-10); with no time words, onset becomes "unknown". A guessed "severe" would raise a false alert. Today's weekday is in the prompt so "since Monday" can be bucketed.
- **Questions come from `survey_cache`, falling back to `schema/examples/survey_config.valid.json`** until A4 fetches the survey through the egress gate. The fallback is temporary.
- **`POST /checkin/turn` rules:**
  - It accepts only loopback clients and `audio/*` content, up to 10 MB and 300 s, as a raw body (no multipart dependency).
  - The recording is never written to disk (PV-03).
  - The raw transcript is returned only to the local screen; the model sees only the filtered text.
  - If extraction fails, the transcript still comes back, with `symptoms: null` and `extraction: "unavailable"`.
  - `question_id` and `ask` are validated but not stored yet (A5).
- **Leakage eval rules:**
  - It passes only with 0 identifiers in the output.
  - An extraction error on any case fails the run.
  - If the model can't run, it exits with code 2 and records nothing.
  - The results file holds counts, types and term codes, never text or identifier values.
- **Patient web:** built pages carry a Content-Security-Policy that allows connections only to the page itself and the runtime, and vitest is pinned to 5.1 (see Errors and fixes).
