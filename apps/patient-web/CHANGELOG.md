# Changelog: apps/patient-web

Changes in this app, newest first. Owned by this app's owner (root `CLAUDE.md`).

## 2026-11-08: Task A7, consent switches and setup, and the sealed copies
- Added: "Set up who I share with" (`SetupScreen.tsx`, `setupFlow.ts`), opened by "Change my choices". Four steps: care team, caregiver (with "Only alerts" or "Alerts and a summary"), emergencies (yes/no, up to 3 hospitals, up to 3 contacts with an optional name that stays on this computer), then a review with "What will be sent" and one "Save and send" (`PUT /consent/setup`). The runtime's 422 message is shown in plain words.
- Added: one sealed copy per organization on the receipt (`envelopes`), and on the summary: "Also sealed for <hospital>: they can open it only in an emergency, and that is logged."
- Added: "Who I share with" page (`ConsentScreen.tsx`, `consentFlow.ts`), opened from the start screen. Two big switches, "Share with my doctor" and "Share with my caregiver" (`role="switch"`, `aria-checked`, whole row tappable, On/Off in words), each with one plain line on what it means. After a change: "Saved and sent.", or "Saved on this device. It will be sent when you're back online." (polled until sent). A switch with nobody set up is disabled with a reason.
- Added: the summary's "What will be shared" has a "Your doctor" section: what is inside the sealed copy in plain words, or "Your doctor gets nothing from this check-in" when sharing is off. "Show exactly what is sent" also lists the sealed copy's fields.
- Added: the receipt shows the doctor's sealed copy (sent, with time and fingerprint; waiting for the hospital's key; or waiting for the connection), and polling continues while it waits.
- Tests: `tests/consent.test.tsx`, `tests/setup.test.tsx`; 232 in total.

## 2026-11-08
- Added: voice commands during questions (VC-07). A turn may come back as `command: "repeat"|"slower"` (or `next.action` repeat/slower): not an answer. The screen replays the same wording at once (slow for "slower"), shows a small "Saying it again" / "Saying it more slowly", and waits for the answer with the same `ask`; it never counts as a re-ask. `command` missing, null or unknown reads as a normal answer.
- Added: spoken summary. The summary reads `spoken` and `correction_used` (missing/null read as no spoken text / false) and is played from `GET /checkin/sessions/{id}/summary/audio?slow=` as soon as it appears; "Hear it again" and "Slower" replay it.
- Added: one correction before sharing (VC-08). A big "Change one answer" (only while `correction_used` is false and not shared): "Say the change" (tap-to-talk recording POSTed raw to `/correction`) or "Tap to change" (pick the item, then Mild/Moderate/Severe, when it started, or "I don't have this"; one tap sends that one change as JSON). The updated summary is shown and read out loud and the option disappears. 422 = "did not understand the change", not used up (say it again or tap); 409 = "cannot be changed again", option hidden and the summary reloaded. The runtime's 422 message is never shown.
- Added: network-off queue (PV-07). A queued receipt says "Saved on this computer. It will be sent automatically when the connection is back." and `GET /checkin/sessions/{id}/receipt` is polled every 5 s (stops on sent/failed, or when the screen is left); when it turns sent the receipt updates in place to "Shared" with time and fingerprint.
- Added: severe-symptom alert line (AL-02) from the receipt's `alert` (missing, null or unreadable = no alert): "Your care team was told about the severe symptom." / "... will be told about the severe symptom when the connection is back." / a failed alert asks to call them. Never names the symptom. Polling also continues while only the alert is queued.
- Added: tests for every new field (incl. missing/null), command replay without a re-ask, correction by tap and by voice (422 not used up, 409), queued receipt polling to sent and stopping (fake timers), alert wording (`tests/summaryOffline.test.ts`, plus `api`, `shareView`).
- Added: re-ask flow (VC-05). `POST /checkin/turn` now reads `rating` (complete, partial, off_topic, rambling, no_answer; null, missing or unknown reads as complete) and `next` (missing or unreadable reads as move on). On a re-ask the screen says "Let me ask that more simply.", shows the new wording as the question and speaks it at once with `ask=<next.ask>` (no tap; Start already unlocked audio); the next answer is sent with that `ask`, and "Hear it again" / "Slower" use it. When the runtime gives a question up (`unanswered: true`) the screen says "That's okay, let's move on." with the usual "Next question" button. Guard: never more than 2 re-asks per question, and never the same or an earlier wording again.
- Added: `src/questionFlow.ts` (no React): `afterTurn` decides re-ask / answered / move on; `createQuestionVoice` fetches, caches and plays each wording. Tests: API parsing of the new fields, a mocked-runtime flow reask -> reask -> next(unanswered) checking audio and turn requests carry ask 0, 1, 2 and each wording plays with only the Start unlock.
- Added: approve-before-share (PV-04). "Start check-in" opens a runtime session (`POST /checkin/sessions`; 503 says in plain words that today's questions were never downloaded) and every answer carries its `session_id`. After the last question the screen shows "Your summary" (`GET /checkin/sessions/{id}/summary`): each problem with how bad and when it started ("today", "1 to 3 days ago", … "start not known"), marked "For review", never as a cause; "You did not report any new problems." when empty; "How bad is the …?" with Mild / Moderate / Severe for any missing severity (choice shown with a tick and words).
- Added: "What will be shared": destination, coded answers only ("no name, no words you said, no recording"), a plain list built from the field names, and a "Show exactly what is sent" toggle with the field names and the record JSON.
- Added: one full-width "Share this" button, disabled until every severity is chosen, the only path to `POST /checkin/sessions/{id}/approve`; "Not now" ends with "Nothing was shared." and a way back to the summary.
- Added: egress receipt (PV-05): status in plain words (Shared / Saved on this device, sent when back online / Not accepted), destination, local time, record number, every field sent and the full `payload_sha256` fingerprint; then "Thank you, that's all for today."
- Added: plain-words errors for an unknown session (Start again), an already shared check-in, a missing severity (409), a record refused by the contract check (422) and a runtime that is not answering (sharing again never sends twice).
- Added: `src/shareFlow.ts` state machine (no React), `src/ShareScreen.tsx`, `src/summaryText.ts`; tests for the new API calls, a mocked end-to-end check that no approve request is made before the tap (plus a static check that only `share()` calls it), and server-rendered view tests. Vitest now also runs `tests/**/*.test.tsx`.

## 2026-11-07

- Added: first check-in screen for Walter: Start check-in (unlocks audio), question in large text spoken by the runtime's local text-to-speech, "Hear it again" and "Slower" (VC-07), full-width tap-to-start/tap-to-stop push-to-talk with no silence cut-off (VC-03), "You said" and symptoms "Noted for review", Next question, closing "Thank you" screen.
